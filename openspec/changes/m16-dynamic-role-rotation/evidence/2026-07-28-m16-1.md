# M16.1 corrective curriculum evidence

## Run diagnosis

`vsss-semantic-run-0004` stopped at iteration 300 after four semantic
regressions. Its outcome accounting was healthy (`14 / 11 / 13`), but the best
max-min checkpoint remained iteration 50 while later checkpoints collapsed
pass and rotation. Inspection of generated scenarios showed the old predicate
only required an incoming touch and goal-side recovery; the third robot stayed
coverage and no complete rotation was measured.

## Corrective checks

- 80 generated blue/yellow rotation scenarios began with the intended
  `(incoming=attacker, former-attacker=support, former-coverage=coverage)`
  assignment.
- The causal predicate test requires the post-play
  `(incoming=attacker, former-attacker=coverage, former-coverage=support)`
  handoff and rejects prolonged uncovered transitions.
- The adaptive allocator test gives the weakest family the greatest allocation
  across 400 selections while sampling every mastered family.
- Difficulty regression tests keep every axis at or above `0.05`.
- `openspec validate m16-dynamic-role-rotation --strict`: valid.

## Gates

- `just build`: passed, including Rust workspace, protocol, Python compilation,
  and the Vite production build.
- Static checks: Rust fmt/clippy, Ruff lint/format, mypy over 98 source files,
  and TypeScript typecheck passed.
- `just test`: passed outside the filesystem sandbox so the loopback ZeroMQ
  transport test could bind; Rust tests, 7 frontend tests, and 191 Python tests
  passed.
- Two-iteration CUDA smoke with 64 vector worlds completed 32,768 environment
  steps and 108 matches without forced stop. It produced checkpoints, replay
  captures, TensorBoard events, semantic evaluations, and family-allocation
  telemetry.

The public semantic recipes now select
`experiments/configs/m16-mappo-rotational-v2.toml`. M16.1 intentionally starts
from a clean policy because the scenario generator and rotation success
semantics changed.
